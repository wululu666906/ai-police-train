# 260812平台大更新开发计划

## 目标

将平台从分散 Prompt 与历史 AI 服务升级为独立的 Agent + Skill + Tool + TinyTroupe + DeepSeek 工作流。旧角色对话和状态推演链路完全删除；平台与 AI 服务保持进程、依赖、数据和故障隔离。

## 核心原则

- Agent 管流程，Skill 管业务能力，TinyTroupe 管角色与世界，DeepSeek 管最终语言生成，Tool 管确定性执行。
- 平台数据库、权限、成绩和正式状态由传统平台独占。
- 状态外化到文件或数据库，不依赖对话上下文。
- 跨边界先定义契约，再实现代码；白名单优先于黑名单。
- Planner、Generator、Evaluator 职责显式分离。
- TinyTroupe 和 Agent 异常不得拖垮平台；不得回退已删除旧链路。

## 实测记录

- Docker 健康检查：`deepseek_configured=true`、`tinytroupe_available=true`。
- Case Import Harness 端到端耗时 53.39 秒；事实 1 条、人物 3 名、角色记忆 3 份，四类训练读取源全部启用。
- 平台 `parse_case_with_agent` 与 `generate_scenes_with_agent` 实调通过，场景直接使用 Harness 蓝图 ID。
- 已删除旧 Skill 的请求由 Pydantic 契约层返回 HTTP 422，无法绕过主业务通道。
- 两次链路审计均覆盖导入、清洗、剧情、事实、人物、记忆、故事世界、场景蓝图全部节点。

## 验收标准

1. `ai_workflow_service` 不导入平台模块，不读取平台数据库配置。
2. 平台代码不直接导入 TinyTroupe。
3. 旧 AI 角色链路及其入口已删除，不存在隐式回退。
4. 案件 Harness 与三个训练阶段 Skill 都有明确输入、输出和错误契约。
5. 所有请求可按 trace ID 定位，写操作具有幂等键。
6. TinyTroupe 或 DeepSeek 失败只影响当前 AI 请求。
7. Harness 审计、项目源码 Python 编译和前端类型检查通过。

## 风险

- TinyTroupe API 不稳定：通过固定提交与单一 Adapter 控制。
- 当前工作区已有大规模未提交精简改动：只在现有基线上修复，不恢复历史实现。
- 历史测试依赖已删除内部函数：删除失效测试，保留与新边界仍一致的测试。
- 本机 Node.js 22.22.0 可用，`vue-tsc --noEmit` 已通过。
- Docker Agent 健康检查实测 `deepseek_configured=true`、`tinytroupe_available=true`；简单 DeepSeek JSON 请求成功。
- DeepSeek 可能返回空 JSON；主链路会拒绝空结果，并使用只基于案件原文的确定性提取保障事实、人物和记忆闭环，不调用旧 AI 链路。
- AI 工作流服务统一使用 `127.0.0.1:8020`；本地开发脚本自动启动并执行健康检查，Compose 内通过服务名的 `8020` 端口访问。
