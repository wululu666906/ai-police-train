# 260812平台大更新开发计划

## 目标

将平台从分散 Prompt 与历史 AI 服务升级为独立的 Agent + Skill + Tool + TinyTroupe + DeepSeek 工作流。旧角色对话和状态推演链路完全删除；平台与 AI 服务保持进程、依赖、数据和故障隔离。

## 核心原则

- Agent 管流程，Skill 管业务能力，TinyTroupe 管角色与世界，DeepSeek 管最终语言生成，Tool 管确定性执行。
- 平台数据库、权限、成绩和正式状态由传统平台独占。
- 状态外化到文件或数据库，不依赖对话上下文。
- 跨边界先定义契约，再实现代码；白名单优先于黑名单。
- Planner、Generator、Evaluator 职责显式分离。
- TinyTroupe 和 Agent 异常不得拖垮平台；不得回退已删除旧链路。

## 验收标准

1. `ai_workflow_service` 不导入平台模块，不读取平台数据库配置。
2. 平台代码不直接导入 TinyTroupe。
3. 旧 AI 角色链路及其入口已删除，不存在隐式回退。
4. 六个 Skill 都有明确输入、输出和错误契约。
5. 所有请求可按 trace ID 定位，写操作具有幂等键。
6. TinyTroupe 或 DeepSeek 失败只影响当前 AI 请求。
7. Harness 审计、Python 编译和前端类型检查通过。

## 风险

- TinyTroupe API 不稳定：通过固定提交与单一 Adapter 控制。
- 当前工作区已有大规模未提交精简改动：只在现有基线上修复，不恢复历史实现。
- 历史测试依赖已删除内部函数：删除失效测试，保留与新边界仍一致的测试。
