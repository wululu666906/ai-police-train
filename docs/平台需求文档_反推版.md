## 2. 项目概述

### 项目背景
平台面向警校生、基层民警和教官，用于案件结构化、角色编排、对话训练、视频实训、评估复盘和知识约束。

### 建设目标
- 把案件文本变成可训练的场景、角色和节点。
- 让学员在模拟现场中完成问答、处置和考核。
- 让教官/管理员高效管理案件、知识库、班级、学员和视频素材。
- 让维护员监控账号生命周期、使用情况和系统异常。

### 平台定位
这是一个“案件知识 + 场景编排 + 交互训练 + 评估复盘 + 运营维护”的一体化训练平台。

### 业务价值
- 降低教官从零搭建训练素材的成本。
- 提升学员训练的可重复性和可追溯性。
- 通过 RAG、AI 角色和视频节点把训练内容标准化。

## 3. 用户与权限

### 用户角色
| 角色 | 代码依据 | 核心目标 |
|---|---|---|
| `admin` | `frontend/src/App.vue`、`backend/routers/*.py` | 维护案件、角色、知识库、班级、视频、学员 |
| `student` | `frontend/src/App.vue`、`backend/routers/student.py` | 参加训练、查看历史、查看评估 |
| `maintainer` | `frontend/src/App.vue`、`backend/routers/ops.py` | 维护账号、使用情况、系统异常 |

### 角色职责
- `admin`：内容生产与发布、训练编排、数据校验、报表查看。
- `student`：进入大厅、发起训练、完成对话/视频节点、查看结果。
- `maintainer`：账号管理、导入导出、重置密码、审计和异常闭环。

### 权限矩阵
| 功能域 | admin | student | maintainer |
|---|---|---|---|
| 案件/角色/知识库 | 是 | 否 | 否 |
| 班级/作业 | 是 | 仅参与 | 否 |
| 普通训练 | 是 | 是 | 否 |
| 视频素材/视频实训 | 是 | 是 | 否 |
| 学员账号 | 是 | 否 | 是 |
| 运维账号 | 否 | 否 | 是 |
| 系统异常/使用监控 | 否 | 否 | 是 |

### 数据权限规则
- 普通训练会话、视频会话默认只能访问本人数据。
- 班级公告、作业、作业提交按班级和成员关系过滤。
- 管理端按账号角色授权，维护端与管理端分离。
- 人脸档案、会话媒体、对象存储资源按 owner 维度绑定。

## 4. 平台业务架构

### 业务模块划分
1. 认证与账号
2. 案件、场景、角色、知识库
3. 班级、作业、学员管理
4. 普通对话训练
5. 视频素材与视频实训
6. 人脸识别与设备门禁
7. 数据质量、运维、异常监控

### 模块关系
案件/知识库为训练提供内容底座；角色与场景决定对话表现；班级把训练下发给学员；视频模块把素材切成可考核节点；人脸模块做身份和在场验证；运维模块做账号和异常治理。

### 整体业务闭环
内容生产 -> 场景/角色编排 -> 发布 -> 学员训练 -> 采集行为与得分 -> 生成报告 -> 教官复盘 -> 运维和数据治理。

## 5. 核心业务流程

### 主业务流程
1. 管理员导入或创建案件。
2. 系统生成场景、角色、考核点或视频节点。
3. 发布到学员端或班级作业。
4. 学员登录并通过人脸/设备校验。
5. 学员进行对话训练或视频实训。
6. 系统记录消息、行为、节点结果、违规和附件。
7. 训练结束后生成评估报告。
8. 教官在后台复盘或修订内容。

### 状态流转
| 对象 | 状态字段 | 典型流转 |
|---|---|---|
| 训练会话 | `active / finished / abandoned` | 开始 -> 进行中 -> 完成/放弃 |
| 视频会话 | `active / finished / abandoned` | 开始 -> 节点执行 -> 完成/放弃 |
| 视频素材 | `draft / published / archived / analyzing` | 上传 -> 分析中 -> 发布/归档 |
| 作业 | `published` 等 | 创建 -> 发布 -> 学员提交 -> 复核 |
| 运维工单 | `pending` 等 | 发现 -> 处理 -> 关闭 |

### 异常流程
- API Key 缺失：回退到本地模板或错误态。
- 人脸不通过：阻断进入训练或记录失败事件。
- 视频分析失败：素材保持草稿/失败态，允许重试。
- 权限不足：统一 403/401。

### 涉及角色和系统动作
- 教官：创建、发布、复盘。
- 学员：训练、提交、查看报告。
- 维护员：导入、重置、审计、处理异常。
- 系统：AI 分析、RAG 检索、评分、状态更新、存证。

## 7. 数据需求

### 核心业务对象
| 对象 | 关键字段 | 说明 |
|---|---|---|
| User | `username/role/display_name/unit/department/account_group` | 账号主体 |
| Case | `title/case_type/background/structured_data` | 案件主表 |
| Scene | `name/difficulty/stages` | 场景 |
| Role | `name/person_id/role_type/interaction_style/persona_meta` | 角色 |
| Knowledge | `content/title/category/library/tags/source_id` | 知识 |
| TrainingClass | `name/invite_code/muted` | 班级 |
| TrainingAssignment | `title/instructions/scoring_rule/status/due_at` | 作业 |
| TrainingSession | `current_stage/current_emotion/current_trust/revealed_info/status` | 普通训练会话 |
| TrainingVideo | `video_type/file_path/thumbnail_path/duration/status/briefing/scenario_type/difficulty` | 视频素材 |
| VideoNode | `trigger_time/pause_mode/node_type/node_interaction_type/choice_options/correct_answer` | 视频节点 |
| VideoTrainingSession | `mode/status/current_node_index/total_score/full_score/node_records/violation_log` | 视频会话 |

### 数据关系
- Case 1:N Scene
- Case 1:N Role
- TrainingClass 1:N TrainingAssignment
- TrainingClass N:M User（通过 ClassMembership）
- TrainingAssignment N:M Case / Scene
- TrainingSession 关联 User、Scene、Case、Role
- TrainingVideo 1:N VideoNode
- VideoTrainingSession 关联 User、Video

### 数据状态
- 视频素材：草稿、分析中、已发布、归档
- 训练会话：进行中、完成、放弃
- 视频节点结果：通过、跳过、超时跳过、失败
- 账号导入：预览、提交、冲突、成功

### 数据生命周期
1. 账号和班级可长期保留。
2. 训练会话可归档但默认保留评估和留痕。
3. 视频会话需要保存节点结果和违规记录。
4. 媒体文件通过本地存储或对象存储保存。

### 数据校验规则
- 人物名必须是纯姓名，不能带身份后缀。
- 视频节点的 `trigger_time` 必须在视频时长内。
- 训练会话状态和评分字段需保持一致。
- 账号导入需预览后再提交。

### 数据导入导出规则
- 支持案件文本、文档、表格、JSON 导入。
- 支持账号导入预览、提交和批量删除。
- 支持视频自动导入目录扫描。

- ffmpeg / ffprobe

### 接口调用规则
- 前端统一通过 `Authorization: Bearer <token>`。
- 视频/训练相关接口默认要校验所有者。
- AI 接口按 provider/model 配置走可切换绑定。
- 失败时前端统一中文提示，不直接暴露英文异常。

### 失败重试和异常处理
- 视频分析可重试。
- 播放预热可重试。
- 语音识别失败记录日志和使用记录。
- 训练/视频提交类接口在前端 toast 兜底。

## 9. 统计报表需求

### 指标名称
- 训练会话数、完成率、平均分
- 视频素材数、发布数、分析失败数
- 学员活跃度、班级作业完成率
- RAG 知识条目数
- 语音调用次数与失败率
- 系统问题单数量

### 指标口径
- 以数据库记录为准。
- 训练完成以 `finished` 或评估完成为准。
- 视频发布以 `status=published` 为准。

### 展示方式
- 管理端仪表盘
- 运维端使用情况页
- 训练/视频报告页

## 10. 非功能需求

### 性能
- 视频上传不得整文件无上限读入内存。
- 播放采用分段预热和缓存。
- 音频转写支持分片并行。

### 安全
- JWT 登录态。
- 生产环境不得使用明文 demo 账号。
- 人脸档案和会话媒体受权限控制。

### 稳定性
- SQLite 支持 busy timeout / WAL。
- 兼容老库的 schema 自动补列。

### 易用性
- 前端统一中文错误提示。
- 学员训练前提供简报和设备检测。

### 兼容性
- 支持浏览器语音识别回退到 WebSpeech。
- 支持本地/对象存储两种资源方式。

### 可维护性
- 模块按 router/service/model 分层。
- AI provider 与业务逻辑分离。

### 日志与审计
- 运维审计、语音使用日志、AI 工作流运行日志、问题单。

### 数据备份与恢复
- SQLite 数据文件、对象存储目录和媒体目录需纳入备份。

## 11. 现有代码实现情况

### 已完整实现
- 登录、角色路由、token 持久化
- 案件、角色、知识库、班级、学员、视频、训练、评估、运维基本闭环
- 人脸注册/验证
- 视频自动分析、节点编排、视频实训

### 部分实现
- 部分训练/评估的细粒度规则仍依赖服务层推断
- 角色审核与 AI 建议存在前端临时逻辑
- 运维导入存在多格式解析，但部分异常分支仍偏工具化

### 未实现
- 统一的工作流审批引擎
- 完整的消息中心/站内信中心
- 系统级报表导出中心

### 疑似废弃功能
- 一些历史清理脚本和旧版迁移脚本

### 前后端不一致功能
- 路由中个别页面是正式页，后端仍保留兼容字段或旧状态字段。

### 数据结构与业务逻辑不一致问题
- 个别训练/视频分析逻辑保留了兼容 fallback，可能与最新 AI 路径并存。

## 12. 问题与风险

### 业务逻辑风险
- AI 自动生成内容可能与人工理解不一致。
- 视频节点的答案出现时刻和触发时刻依赖分析质量。

### 权限风险
- 需要持续确认 student/admin/maintainer 的边界。

### 数据风险
- 兼容老库时会自动补列，存在历史数据差异。

### 安全风险
- 外部 LLM、ASR、对象存储密钥必须只读环境变量。

### 流程断点
- 视频分析失败后，素材会停在草稿/失败态，需要人工重试。
- 人脸未注册时训练入口会被阻断。

### 潜在缺陷
- 训练与视频两个评估系统并行，报表口径要统一。

## 13. 待确认事项

1. 学员端和管理员端是否允许同账号双角色切换。
2. 视频素材“分析失败”是否允许自动后台重试。
3. 班级作业的补交和例外策略是否需要审批流。
4. AI 生成的训练节点是否必须人工审核后发布。
5. 运维端账号导入的最终字段口径是否固定。

## 14. 后续优化建议

### 必须完善项
- 统一所有报告的口径和字段。
- 明确 AI 生成内容的审核与发布责任。
- 把关键状态流转固化成统一枚举。

### 建议优化项
- 把训练/视频/运维异常沉淀成统一工单中心。
- 把知识库、案件库、视频库的检索入口统一。

### 后续扩展项
- 更完整的审批流
- 更细的组织架构与数据权限
- 多租户或多单位隔离

### 功能优先级建议
1. 必须先稳住登录、训练、视频分析、评估链路。
2. 再完善运维和报表。
3. 最后做高级审批、跨系统对接和扩展分析。
