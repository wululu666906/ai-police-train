# AI虚拟警情处置模拟训练平台测试活动方案

**版本：** v1.0  
**编制日期：** 2026年7月18日  
**适用对象：** 测试组织者、教官/管理员、学员测试人员、技术保障人员

## 一、活动背景与目标

AI虚拟警情处置模拟训练平台面向警校学生、岗前及在职培训民警，支持“案例配置—场景训练—AI多轮对话—评估复盘”的训练闭环。本次测试活动以真实使用者集中试用为核心，通过管理员端、学员端及必要的维护保障协同验证，检验平台在教学训练场景下的可用性、稳定性和业务适配性。

本次活动不以单纯“页面可打开”为通过标准，重点验证以下结果：

1. 测试人员能够独立完成案例配置、发布、训练、评估和历史复盘。
2. AI角色回应能够围绕模拟案情持续、多轮、合理地展开，并保持角色与案情一致。
3. 评估报告能够对应训练过程中的考察点和处置动作，提供可理解的改进建议。
4. 多人同时训练和生成报告时，平台保持基本可用，数据不串号、不丢失。
5. 账号权限和训练数据边界清晰，学员、管理员与维护人员不能越权访问。

## 三、组织分工

| 角色 | 建议人数 | 主要职责 |
|---|---:|---|
| 总协调人 | 1人 | 确认活动流程、统一口径、协调现场资源、宣布测试开始和结束 |
| 教官/业务观察员 | 1—2人 | 审核模拟案情与处置逻辑，观察AI业务表现和评估有效性 |
| 技术保障人员 | 1—2人 | 测试环境巡检、账号与网络保障、日志定位、P0/P1问题应急处置 |
| 现场秩序与记录人员 | 1—2人 | 签到、分发账号和材料、计时、拍照、汇总问卷及缺陷单 |
| 测试人员 | 约50人 | 按编号完成双端测试闭环，提交体验反馈和问题记录 |

建议采用“测试编号”管理：每名测试人员领取一组独立管理员账号与学员账号，例如`admin_test_01`与`student_test_01`。新建的案例、场景、角色、班级等数据均以“【T01】”开头，避免多人数据混淆。

## 四、测试前准备

测试前1天由组织者、教官和技术保障人员完成以下事项：

- 确认测试环境可从现场设备访问，平台地址、HTTPS/证书、浏览器兼容性和网络策略正常。
- 创建并核对独立测试账号，建立“人员—测试编号—管理员账号—学员账号”对应表；不得使用生产默认密码。
- 准备统一的脱敏模拟案情包。每份至少包含案例背景、2个角色、1个训练场景、3个考察点和1份知识库小文档。
- 使用一组测试账号完整走通“管理员建案发布—学员训练—评估报告—历史复盘”流程。
- 明确本轮启用功能。未启用的视频、语音或其他模块应提前说明，测试人员统一标记为“未配置/不适用”。
- 备份测试前数据，明确测试数据的归档或清理策略；测试过程不得使用真实姓名、身份证号、电话、住址或未公开案件信息。
- 建立唯一的问题反馈入口，公布总协调人和技术保障人员联系方式，并准备统一计时点。

## 五、活动流程与时间安排

| 阶段 | 建议时长 | 主要内容 | 完成标志 |
|---|---:|---|---|
| 签到与说明 | 0—15分钟 | 签到、领取账号与材料，说明测试纪律、隐私要求和问题上报方式 | 每人获得测试编号及双账号 |
| 管理端建案发布 | 15—75分钟 | 登录管理端，配置案例、角色、场景和考察点，发布训练；验证已启用的知识库、班级/作业等功能 | 本人编号的训练场景已发布 |
| 学员端训练 | 75—120分钟 | 切换学员账号，找到指定训练，完成不少于8轮有效对话 | AI可连续回应，训练会话正常保存 |
| 评估与复盘 | 120—145分钟 | 结束训练，生成评估报告，查看训练历史和对话记录，再次登录确认数据保留 | 报告与历史记录可正常访问 |
| 并发验证与反馈 | 145—165分钟 | 全员按统一时间提交消息和生成报告，填写问卷与缺陷单 | 并发结果和问题记录完成汇总 |
| 现场复盘与收尾 | 165—180分钟 | 汇总关键问题、宣布初步结论、明确修复与回归安排 | 形成测试结论及后续责任人 |

## 六、测试范围与执行要点

### 1. 管理端

每名测试人员使用本人管理员账号，完成以下验证：

- 登录后进入正确的管理端工作区；刷新页面后无白屏、乱码或错误跳转。
- 新建带编号的案例，填写案例名称、类型、背景、人物关系、冲突点和关键信息；保存后再次打开，内容不丢失。
- 至少创建2个角色、1个训练场景和3个考察点，检查角色绑定、场景校验和保存结果。
- 发布本人训练场景，确认已发布内容可被对应学员端看到，未发布内容不应对学员可见。
- 对本轮已启用的知识库、班级/作业、学员管理、数据质量、个人中心和视频资源进行基本操作验证。
- 管理员账号不得获得维护端账户管理权限。

### 2. 学员端

每名测试人员使用配对学员账号，完成以下验证：

- 登录后进入学员端，查看训练大厅并按类型或难度进行一次筛选。
- 找到本人编号对应的已发布训练，核对案例简介、接警简报、角色和场景信息。
- 完成不少于8轮有效对话。对话应覆盖身份与安全、时间地点、人物关系、事件经过、证据线索、情绪沟通、规范处置和闭环确认中的至少6类内容。
- 结束训练并生成评估报告，检查总评、考察点完成情况、评分依据和改进建议是否与本次对话相符。
- 在训练历史中重新打开对话记录和评估报告；退出后再次登录，确认记录仍可访问且只属于本人。
- 学员账号直接访问管理端页面时，应被拦截并返回登录页或学员工作区。

### 3. 跨端闭环、并发与异常恢复

- 管理端发布的案例、场景和作业，应在配对学员端正确可见；学员完成训练后，管理端应能看到对应状态或统计结果。
- 统一并发窗口建议持续10分钟：全员同时保持登录、进入场景、发送2条有效消息、集中生成报告、从历史重新打开报告。
- 在完成3轮对话后，允许进行一次正常刷新或从历史继续训练，检查消息、进度和会话是否保留。
- 发现问题时先截图、记录时间和操作步骤；等待30秒后仅尝试一次正常返回或重新进入。仍失败则停止重复操作并上报。

## 七、验收标准与问题分级

| 验收项 | 建议通过目标 | 不通过信号 |
|---|---|---|
| 双账号登录 | 不少于49/50人可分别登录并进入正确工作区 | 多人无法登录、角色跳错、反复跳转 |
| 管理端建案发布 | 不少于45/50人独立完成案例、角色、场景和3项考察点的发布 | 保存失败、发布后学员端不可见、数据串号 |
| 学员训练闭环 | 不少于45/50人完成8轮有效对话并生成报告 | 训练或评估被同类问题持续阻断 |
| 跨端一致性 | 不少于95%的配对数据在两端正确对应 | 发布/训练/报告状态不同步，未发布内容可见 |
| AI与评估质量 | 不少于80%的测试者认为AI回应和报告基本贴合对话 | 大量答非所问、角色混乱、评分无依据 |
| 并发稳定性 | 50人同时在线；不少于40人可在5分钟内完成消息提交；报告窗口无全局不可用 | 大面积5xx、白屏、消息重复或串号、服务崩溃 |
| 权限与隐私 | P0问题为0；任何人均不可访问他人训练详情 | 越权访问、数据泄露、跨账号修改、密码或令牌泄露 |
| 易用性 | 不少于85%的测试者无需额外讲解完成关键路径；总体评分不低于4.0/5 | 多数测试者找不到发布、开始训练、报告或历史入口 |

| 级别 | 定义 | 处理要求 |
|---|---|---|
| P0 致命 | 越权、数据泄露、数据串号、平台整体不可用 | 立即停止相关测试，通知负责人；本轮测试不通过 |
| P1 严重 | 主流程被阻断且无可接受绕过方式 | 现场立即上报，保留截图和发生时间，安排优先修复 |
| P2 一般 | 功能可继续，但结果不准确或体验明显受损 | 测试结束前提交完整缺陷记录，纳入修复清单 |
| P3 建议 | 文案、视觉或低影响体验优化 | 纳入后续体验优化清单 |

出现任一P0问题，本轮测试直接判定为不通过；同一P1问题导致5人以上无法完成管理端发布或学员训练时，应在修复后重新验证关键闭环。

## 八、现场纪律与数据安全

- 每人仅使用本人分配账号，不得共用账号、猜测他人密码或修改他人编号的数据。
- 测试内容只使用组织者提供的脱敏模拟材料，不输入真实个人信息、未公开案件信息或其他敏感数据。
- 截图、录屏和问题单中不得暴露密码；必要时遮盖无关个人信息。
- 除异常恢复任务外，不清除浏览器缓存、不删除训练记录、不强制关闭页面、不连续重复提交请求。
- 遵守现场秩序与统一并发指令；涉及语音或视频测试时应佩戴耳机，并在相对安静的区域操作。

## 九、问题反馈与成果输出

### 问题记录最小信息

每条问题至少包含：问题标题和级别、测试编号、发生时间、平台地址、浏览器及设备信息、账号名（不含密码）、案例/场景、前置条件、复现步骤、实际结果、期望结果、截图或录屏、复现频率。

### 活动结束后输出

1. 测试签到与账号发放记录。
2. 双端完成率、并发结果、体验问卷和缺陷清单。
3. P0/P1问题应急处置记录及修复责任人。
4. 《测试总结报告》：包括通过/有条件通过/不通过结论、主要发现、数据指标、修复优先级和回归测试范围。
