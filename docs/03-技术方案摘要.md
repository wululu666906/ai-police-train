# AI虚拟警情处置模拟训练平台 — 技术方案摘要

**版本**：v1.0  
**读者**：技术负责人、信息化运维、集成开发人员

---

## 一、技术栈总览

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue 3 + Vite + Vant + Pinia | 管理端与学员端统一 SPA |
| 后端 | FastAPI + SQLAlchemy | REST API，AI 友好 |
| 数据库 | SQLite（默认）/ PostgreSQL（可选） | 默认 `backend/ai_police.db` |
| 大模型 | 可配置 LLM Provider（如 DeepSeek 等） | 通过 `llm_provider` 等服务接入 |
| 知识检索 | RAG（向量检索 + 知识库表） | 法律、规范、话术约束 |
| 语音 | 讯飞 ASR（可选）+ Web Speech | 学员端语音输入 |
| 部署 | Docker Compose | 根目录 `docker-compose.yml` |

## 三、AI 对话引擎（核心）

训练对话非「直接 Chat」，而是分层 pipeline：

```
用户输入
  → 对话状态（情绪、信任、已释放信息）
  → 场景引擎（阶段、目标）
  → 角色引擎（人设、行为规则）
  → 知识库检索（RAG）
  → Prompt 构建
  → LLM 生成回复
```

### 3.1 关键后端服务（示例）

| 模块 | 职责 |
|------|------|
| `scene_conversation_engine` | 场景对话编排 |
| `multi_role_service` / `multi_role_director` | 多角色调度 |
| `persona_engine` | 角色人设 |
| `stage_config_service` | 阶段配置与覆盖评估 |
| `recommended_questions_service` | 推荐问句 |
| `evaluation_service` | 训练结束评分与考察点评估 |
| `ai_service` | 对话生成与训练动作 |
| `state_influence_engine` | 角色四维度状态引擎（情绪、信任度、配合度、风险意识），根据对话实时更新参数 |
| `state_influence_config` | 四维度阈值配置，定义不同阈值区间内的角色行为策略 |
| `state_influence_metrics` | 维度指标计算与状态追踪 |
| `assessment_point_import_service` | 考察点导入与自动切分（支持文件/模板导入） |
| `scene_bucket_service` | 场景桶管理与场景分组编排 |
| `ai_roles` | AI 角色动态行为规则与角色表现微调 |

### 3.2 Prompt 体系

项目内 `提示词设计.md` 定义多类 Prompt，新增考察点相关提示词：

1. 案件文本结构化解析  
2. 训练场景生成  
3. AI 对话角色（通用模板）  
4. 自动评分  
5. 复盘报告生成  
6. **考察点生成与评估**：根据案件内容自动生成考察点，结合模板切分考察项  
7. **评估点警官提示词**：`assessment_point_officer.py` — 按考点评分逻辑进行结构化评估  
8. **训练语音分层提示词**：`training_voice_layers.py` — 语音识别后处理与分层策略  

所有 Prompt 强调 **JSON 结构化输出** 与 **信息分轮释放**，避免模型自由发挥导致不可控。

## 四、数据模型（核心实体）

| 实体 | 用途 |
|------|------|
| User | 管理员、学员账号与角色 |
| Case | 案件主数据（类型、背景、结构化字段） |
| Scene | 训练场景（阶段、难度、角色列表） |
| Role | 公共模板或案件人物（含四维参数配置） |
| TrainingSession | 学员一次训练会话 |
| Message | 对话消息（含说话角色） |
| Knowledge | 知识库文档与检索 |
| AssessmentPoint | 考察点定义（关联案件，支持模板导入与自动切分） |
| StateInfluenceConfig | 四维度阈值配置（情绪、信任度、配合度、风险意识） |

## 五、部署说明

### 5.1 本地开发

```bash
# 后端
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python init_db.py
uvicorn main:app --host 127.0.0.1 --port 8000

# 前端
cd frontend
npm install
npm run dev
```

- 前端：`http://localhost:5173`  
- API 文档：`http://127.0.0.1:8000/docs`

### 5.2 生产部署

```bash
cp backend/.env.example backend/.env
docker compose up -d --build
```

详见根目录 `DEPLOY_TENCENT_CLOUD.md`。

### 5.3 安全提醒

- 生产环境必须更换 `JWT_SECRET_KEY`  
- 勿提交真实 `.env`  
- 公安内网场景建议全链路私有化，LLM 与语音服务均走内网 endpoint

## 七、技术演进路线（与开发方案对齐）

| 阶段 | 内容 |
|------|------|
| **MVP（当前）** | 案件结构化、场景训练、多轮对话、基础 RAG、自动评分、双端 Web、考察点导入与自动切分、语音自动发送、角色四维参数影响引擎 |
| **第二阶段** | ASR/TTS 完善、多模态笔录、复盘报告增强、角色/场景配置模板简化、四维度触发机制精细化 |
| **第三阶段** | 视频解析、VR/插件生态、与教务系统对接 |

---

## 八、关键技术难点

1. **多模态案件解析**：视频/录音/文书统一结构化（规划项）。  
2. **评分可信度**：可解释、可复核、引用对话原文。  
3. **大模型幻觉**：RAG + 行为规则 + 信息释放控制。  
4. **内网限制**：模型、向量库、对象存储均需支持离线/私有化。
