# 角色四维属性与状态机联动说明

## 1. 四维属性定义

| 属性 | 指标释义 | 对角色行为、对话与决策的影响 |
| --- | --- | --- |
| 情绪 `emotion` | 当前唤醒度、压力和激动程度 | 影响语气强度、打断概率、句长与表达节奏；不直接改变角色掌握的事实 |
| 配合度 `cooperation` | 对执法人员的披露意愿与互动意愿 | 决定回答深度、主动补充程度和每轮可披露的新事实数量 |
| 风险 `risk` | 失控、冲突升级或安全事件发生的倾向 | 决定安全边界、插话和升级动作优先级，高风险时阻断训练阶段推进 |
| 清晰度 `clarity` | 表达连贯性、自我纠正能力与时间线组织能力 | 决定台词是否完整、跳跃、重复或需要民警进一步澄清 |

四维值范围统一为 `0-100`。模型只生成角色台词和轻量建议，不拥有数值决策权，也不能直接修改会话快照。

## 2. 初始化规则

新训练会话通过 `role_state_service.resolve_role_initial_state` 构造四维快照，优先级为：

1. 人工配置值。
2. 案件结构化人物值或角色元数据值。
3. 开场预设值。
4. 行为原型、身份类型兜底值。

同类角色会根据稳定身份散列获得 `-4` 至 `+4` 的确定性微调，以避免全员同值，同时保证同一角色重复初始化结果一致。存量回填仅处理缺失值和遗留默认值；明确人工值不覆盖，已开始会话的运行时快照不参与迁移。

## 3. 表达控制权重

角色表达能力的综合控制权重保持为：清晰度 `55%`、配合度 `10%`、风险反向 `15%`、人格储备 `12%`、情绪反向 `8%`。人格储备来自角色剧本与行为原型，不是第五个运行时状态轴。

权重只决定语言表现上限和披露节奏，不能突破人物记忆、身份边界和案件事实。事实边界始终高于语言风格规则。

## 4. 数值驱动规则

每轮先由可审计的学员问法、处置动作、场景刺激和人物修正规则计算变化，再写入角色快照。普通单轮各轴最大变化为 `±12`；明确的降级、安抚和紧急安全处置可按现有影响规则使用例外上限。

处理顺序为：识别输入与动作 -> 计算人物反应 -> 计算四维变化 -> 构造状态契约 -> 生成并校验台词 -> 持久化快照。模型返回的 `state_delta` 只作受限建议，最终值由状态影响引擎裁剪和合并。

## 5. 混合状态机

角色四维混合状态按以下优先级判定：

1. `crisis`：风险达到危机阈值。
2. `confused`：清晰度低于混乱阈值。
3. `resistant`：配合度低于抵触阈值。
4. `agitated`：情绪达到激动阈值。
5. `engaged`：配合度和清晰度支持有效互动。
6. `guarded`：其余防备、观望状态。

状态切换采用 `5` 点滞回：进入阈值和退出阈值相差 5 点，避免数值在边界附近造成状态反复抖动。状态契约控制口吻、披露量、打断和安全反应，但不写入新事实。

## 6. 两类状态机的调用关系

训练阶段状态机管理“当前处置进行到哪一步”，依据阶段目标、必做动作和评估点推进。角色四维混合状态机管理“人物此刻如何反应”。两者独立持久化，在每轮对话中由训练运行时统一调用。

当角色处于 `crisis`，或当前阶段必需目标、动作、评估点尚未完成时，阶段状态机禁止推进。角色恢复到安全范围且阶段条件满足后，才允许切换下一阶段。

## 7. 对话上下文与开场

开场角色的四维快照和常规对话使用同一初始化服务。多角色每轮生成前读取全量累计摘要和最近 12 条原文；同角色历史相似度达到 `0.78`、跨角色达到 `0.86` 时重试一次。重试仍重复时，只允许用尚未使用且有来源的角色记忆事实修复，否则抑制该气泡。

场景开场通过 `opening_config` 配置开关、动态或预设模式、最多三名有序角色、导演约束与预设台词。开场消息写入消息表并记录 `opening_message_ids`，`opening_delivered` 保证恢复或刷新会话时不会重复生成。
# 场景级初始化与对话记忆（2026-08）

## 场景角色状态优先级

训练运行时优先读取 `scene_roles.initial_state`。该 JSON 保存情绪、配合度、风险和表达清晰度，以及生成来源、规则版本、输入摘要哈希和生成时间。角色表中的旧四维字段只用于旧数据兼容，不再作为场景训练的首选来源。

新建、重建或编辑案件时，系统以案件背景、当前场景描述、训练阶段、角色身份状态、本人记忆和人物画像为输入生成场景状态。相同输入通过摘要哈希保持稳定；场景或人物输入变化后重新计算。旧数据库在启动兼容迁移中仅使用现有剧情资料进行确定性回填，不调用外部模型。

## 会话上下文

`messages` 表按 `created_at, id` 保存从开场到结束的完整原文，是审计与恢复的唯一事实源。LangGraph `StateGraph` 在每轮对话中从该表装载历史并输出四层工作上下文：较早对话工作摘要、与当前问题相关的较早原文、最近 12 条原文、按角色隔离的私有线程。运行状态中的 `agent_context` 只保存上下文版本、水位和派生视图，不能覆盖或删除原始消息。

服务重启、缓存缺失或消息水位不一致时，系统直接从完整消息表重建上下文。其他角色的公开台词可作为现场信息，但不会进入当前角色的本人记忆。
